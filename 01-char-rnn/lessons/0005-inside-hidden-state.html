1　把结论变成数字

「词边界处变化明显」可以这样量：计算相邻两步的 ‖h_t − h_{t−1}‖，比较读到空格或换行的时候和其他时候。「单元对空格反应强烈」可以这样量：每个单元的值和「当前是否空格」的相关系数。

我在 438 字符的完整文本上算了三个模型（均为 3000 步，种子 42）：

模型‖Δh‖：边界处‖Δh‖：其他最大 |相关||h| > 0.9 的比例下一字符准确率
lr = 0.01（notebook）6.307.110.4793.6%73.9%
lr = 0.00312.6912.810.4446.0%99.8%
lr = 0.00111.8711.960.4639.2%99.3%

结果和 print 的说法不符：

  • 词边界处的变化并不更大。三个模型都是边界处略小或几乎相等。
  • 没有单元和空格强相关。128 个单元里，三个模型都没有相关系数超过 0.5 的。
  • 第三句没有被这张图证明。Notebook 的 lr = 0.01 模型有 93.6% 的值挤在 ±1 附近，热图上那些深红深蓝主要是饱和，不是有意义的结构。

但这不代表 RNN 没有编码信息。lr = 0.003 的模型准确率 99.8%，上下文显然就在 h 里。只是它分散在许多单元上，W_hy 的线性组合能读出来，单看一个单元看不出来。我的相关系数只测单个单元，所以只能否定「某个单元」这种说法。

Karpathy 确实找到过可解释的单元，比如 URL 内外、引号内外。但那是在大数据上训练的 LSTM，他估计约 5% 的单元有趣，大部分解释不了，并直言这些结论有点「hand-wavy」，隐藏状态是高度分布式的表示[1, Visualizing the predictions]。这和 notebook 的玩具模型不是一回事。

2　tanh 是必须的吗

思考题 3 问为什么用 tanh 而不用 ReLU。我把手写版的 tanh 换成 ReLU，其他不变（裁剪 5.0，3000 步，3 个种子）：

激活函数lr最后 500 步平均损失h 的最大值
tanh0.0030.006、0.007、0.007≤ 1
ReLU0.0030.059、0.071、0.05011 到 14
ReLU0.0010.056、0.051、0.06719 到 401

ReLU 也能学，没有出现 NaN，只是这里损失高了约 10 倍。差别在于 ReLU 没有上界：状态可能越滚越大，这正是第 3 课说的范数大于 1 时那种爆炸的土壤。tanh 把状态关在 (−1, 1) 里，代价是第 3 课看到的饱和和梯度衰减。这是取舍，不是对错。这里只是一个玩具数据上有裁剪的结果，不足以推广。

3　内建 nn.RNN 和手写版

Notebook 第 8 节标题叫「比较」，其实只建了模型、打印了参数量，没有训练。我把比较做完。

先看对应关系。Karpathy 的公式就是 nn.RNN 默认的计算[2]：

手写nn.RNN 里的名字说明
W_xhweight_ih_l0输入到隐藏
W_hhweight_hh_l0隐藏到隐藏
b_hbias_ih_l0 + bias_hh_l0内建有两个偏置，相加才是一个 b_h
W_hy, b_y另外的 nn.Linearnn.RNN 只管隐藏状态，不含输出层

把手写版的权重拷进 nn.RNN，同一段 100 字符的输入，两边输出的最大差别是 1.25 × 10⁻⁶，只是浮点误差。它们是同一个模型。

Notebook 的内建版参数更多（39192 对 22680），不是因为 RNN 不同，而是它先用了 nn.Embedding 把字符变成 128 维，于是输入权重从 128×24 变成 128×128，还多了一个 3072 的嵌入矩阵和一个偏置。

练习 C：把权重对上

补全那 6 行拷贝，让 nn.RNN 和手写版输出一致。nn.RNN 默认输入形状是 (序列长, 批量, 输入维度)[2]。

import torch
import torch.nn as nn
import torch.nn.functional as F

V, H = 24, 32
torch.manual_seed(0)
W_xh, W_hh = torch.randn(H, V) * 0.1, torch.randn(H, H) * 0.1
W_hy, b_h, b_y = torch.randn(V, H) * 0.1, torch.randn(H) * 0.1, torch.randn(V) * 0.1

rnn = nn.RNN(V, H)
fc = nn.Linear(H, V)
with torch.no_grad():
    # 把 W_xh, W_hh, b_h, W_hy, b_y 拷进去，并处理多出来的那个偏置
    ...

seq = torch.randint(0, V, (50,))
h, mine = torch.zeros(H), []
for i in seq:
    h = torch.tanh(W_xh[:, i] + W_hh @ h + b_h)
    mine.append(W_hy @ h + b_y)
mine = torch.stack(mine)

out, _ = rnn(F.one_hot(seq, V).float().unsqueeze(1))
theirs = fc(out).squeeze(1)
assert (mine - theirs).abs().max() < 1e-5, "两边输出应该一致"
print("全部通过，最大差别", (mine - theirs).abs().max().item())

4　总复习

五个问题各来自一课，不看前面的内容回答。

第 1 课：为什么 step(x_t) 的输出能依赖更早的字符？

  1. 输入里拼接了历史
  2. 权重每一步都不同
  3. 旧状态经由 W_hh 传入
  4. 输出层记录了历史

x_t 只是当前字符，历史全部压缩在 h_{t−1} 里，通过 W_hh 进入这一步。

第 2 课：notebook 损失曲线的高起点来自什么？

  1. 总和初值配平均损失
  2. 学习率设得实在太大
  3. 梯度裁剪的阈值太小
  4. 模型一开始就有饱和

初值 ln V × 25 是总和尺度，CrossEntropyLoss 默认却取平均。

第 3 课：下面哪个是 h.detach() 的效果？

  1. 状态归零梯度回传
  2. 状态归零梯度断开
  3. 状态传递梯度回传
  4. 状态传递梯度断开

数值照常传给下一块，计算图在这里断开。

第 4 课：T → 0 时，采样退化成什么？

  1. 均匀随机抽字符
  2. 每步取最大概率
  3. 每步取最小概率
  4. 重复上一个字符

概率比的指数 1/T 趋于无穷，最高分字符的概率趋于 1。

本课：nn.RNN 和手写版权重对齐后，输出关系如何？

  1. 只有形状一样
  2. 相差一个系数
  3. 只差浮点误差
  4. 方向恰好相反

实测最大差别约 10⁻⁶，它们是同一个模型。
