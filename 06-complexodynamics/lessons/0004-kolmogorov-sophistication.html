第 4 课 · 复杂动力学第一定律

最短程序，与程序里「不随机」的那一半

Kolmogorov 复杂度为什么量不出「有趣」，以及 sophistication 怎样把一段描述拆成模型和噪声

第 3 课的结论是：压缩长度能分开「有规律」和「随机」，但随机串的压缩长度最大，而随机串一点也不有趣。Aaronson 说，Kolmogorov 本人在 1970 年代就注意到了同一件事[1]：

A uniformly random string, he said, has close-to-maximal Kolmogorov complexity, but it's also one of the least "complex" or "interesting" strings imaginable. After all, we can describe essentially everything you'd ever want to know about the string by saying "it's random!"

这一课先把压缩长度背后的理想对象 K(x) 讲严格，证明它的两个基本事实，再按 Aaronson 原文定义 sophistication：一个想要「两头都低、中间才高」的量。

本课收获：你能用计数论证证明「绝大多数串不可压缩」，用 Berry 悖论证明 K 不可计算，并能对给定的串写出两段式描述、算出模型部分和下标部分各要多少位。

1　定义：K(x) 是输出 x 的最短程序长度

固定一种「图灵通用」的编程语言 U。串 x 的 Kolmogorov 复杂度定义为[1][2]：

KU(x) = min { |p| : 程序 p 在 U 上运行后输出 x 并停机 }　　单位：bit

两条马上能看出来的性质：

  • 上界。K(x) ≤ |x| + c：程序「print "x"」就输出 x，它的长度是 x 本身加上一段固定的外壳 c。
  • 不变性定理。换一种通用语言 V，|KU(x) − KV(x)| ≤ cUV，常数与 x 无关。理由：在 U 里写一个 V 的解释器，长度固定为 c；任何 V 程序前面接上这个解释器，就成了 U 程序。反方向同理。所以我们通常省掉下标，写 K(x)。Aaronson 说的「the exact choice can be shown not to matter much」就是这条定理[1]。

K 小，表示 x 有很短的描述，即有规律。全 0 串 0ⁿ 只要「打印 n 个 0」，长度约 log₂ n + c。第 1 课的 Rule 30 也是一例：100 个格子演化 t 步之后的那一行，看起来很乱，但「从中间一个 1 开始跑 Rule 30 共 t 步」这段描述只要一个固定长度的程序加上 t 这个数，约 log₂ t + c 位。

2　证明：绝大多数串不可压缩

称 x 为 k-可压缩的，如果 K(x) < |x| − k。下面的论证只用到「一个程序最多输出一个串」。

数程序。长度为 0, 1, …, n−k−1 的二进制程序一共有 2⁰ + 2¹ + … + 2ⁿ⁻ᵏ⁻¹ = 2ⁿ⁻ᵏ − 1 个。

数串。每个程序最多输出一个串，所以满足 K(x) < n − k 的长度为 n 的串，最多 2ⁿ⁻ᵏ − 1 个。

比例。长度为 n 的串共 2ⁿ 个，其中 k-可压缩的不到 2ⁿ⁻ᵏ ⁄ 2ⁿ = 2⁻ᵏ。

两个推论。取 k = 0：长度 n 的串里至少有一个满足 K(x) ≥ n，一位都压不掉。取 k = 10：超过 1 − 2⁻¹⁰ ≈ 99.9% 的串连 10 位都压不掉。∎

这就是「随机」的算法定义：一个串不可压缩，就说它是随机的。注意论证里没有用到任何概率，只是在数个数。

3　证明：K 不可计算

既然 K 这么好，为什么 notebook 和 Aaronson 都改用 gzip？因为根本不存在一个程序，输入 x 就输出 K(x)。证明是 Berry 悖论的形式化：「不能用少于十八个字描述的最小正整数」这句话本身不到十八个字[2]。

假设有程序 Q 能算 K(x)，Q 的长度是固定的常数。

构造程序 Pm：按长度从短到长、同长按字典序枚举所有串 x，对每个 x 调用 Q，输出第一个满足 K(x) ≥ m 的 x 后停机。由第 2 节（k = 0），长度为 m 的串里一定有这样的 x，所以 Pm 必然停机。

量长度。Pm 由 Q、固定的枚举外壳和数 m 组成，长度 ≤ c + log₂ m，c 是与 m 无关的常数。

矛盾。Pm 输出的 x 满足 K(x) ≥ m（按 Pm 的选法），又满足 K(x) ≤ |Pm| ≤ c + log₂ m（Pm 就是输出 x 的一个程序）。于是 m ≤ c + log₂ m。但 m − log₂ m 随 m 无界增长，取 m 足够大就不成立。所以 Q 不存在。∎

能算的只是上界：任何一个能还原 x 的压缩器，它的输出长度加上解压器长度，都 ≥ K(x)。压缩器越好，上界越紧，但永远不知道离 K 还差多少。Aaronson 在文末正是这样建议的：用 gzip 文件大小「作为 K(x) 的粗糙替身」[1]。

替身差多远：两个实测

下面的数字我用 Python 的 zlib.compress(x, 9) 实测过（随机字节用 random.Random(0).randbytes 生成）：

输入原长（字节）压缩后（字节）
全 010 00033
随机字节10 00010 011
同一段随机字节拼两遍20 00010 163
Rule 30，宽 4001，第 2000 步的那一行（每 8 格打包成 1 字节）501512

前三行符合理论：随机串压不动，压缩后反而多了 11 字节的外壳；重复一遍几乎不增加长度，因为第二遍可以写成「把前面那段再抄一次」。第四行是替身的盲区：zlib 压不动这一行，但它的 K 很小，只要 Rule 30 的规则、宽度 4001 和 t = 2000 这几个数，后者约 11 位。zlib 只会找重复片段，看不出「这是某条简单规则跑出来的」。

4　sophistication：只数描述里「不随机」的那部分

K 把规律和噪声算在一起，随机串的 K 最大。Kolmogorov 的想法是把描述拆成两段：先说「x 属于集合 S」（模型），再说「是 S 里的第几个」（下标）。下标最多 ⌈log₂|S|⌉ 位。如果 x 在 S 里毫无特殊之处，下标这一段就是纯噪声，「结构」全在模型那一段。

Aaronson 的定义如下[1]。设 S 是一个 n 位串的集合，K(S) 是输出 S 全部元素后停机的最短程序长度；K(x|S) 是在「可以查询某个串是否属于 S」的条件下输出 x 的最短程序长度。则：

let the sophistication of x, or Soph(x), be the smallest possible value of K(S), over all sets S such that
1. x ∈ S; and
2. K(x|S) ≥ log₂(|S|) − c, for some constant c. (In other words, one can distill all the "nonrandom" information in x just by saying that x belongs to S.)

条件 2 说的是：知道 S 以后，x 已经没法比「直接报下标」描述得更短了。也就是说，x 是 S 里一个「典型」的、看起来随机的成员，没有剩下的规律可挖。

用三个 n 位的串看看它对两头的表现：

x选的 SK(S)（模型）log₂|S|（下标）
全 0：0ⁿ单点集 {x}≈ log₂ n0
均匀随机全体 {0,1}ⁿ≈ log₂ nn
前一半全 0、后一半随机{0n/2y : y ∈ {0,1}n/2}≈ log₂ nn/2

前两行就是 Aaronson 说的：简单串和随机串的 sophistication 都很小。第一行条件 2 自动成立（log₂|S| = 0）；第二行成立是因为随机的 x 在 {0,1}ⁿ 里本来就是典型元素。

第三行要多想一步。直觉上它「一半有结构、一半随机」，像是介于两端之间，但它的 sophistication 照样只有 log₂ n 这个量级：模型「前一半是 0」很短，剩下的全是噪声。这说明 sophistication 高不等于「有结构的部分多」，而是「描述这些结构本身就需要很多位」。随便造的例子很难做到这一点。Aaronson 提到，「到底存不存在 sophistication 高的串」曾是 Kolmogorov 提出的问题，1980 年代初才由 Alexander Shen 用对角化构造肯定地回答[1]。

第 5 课的伏笔：Aaronson 紧接着指出，sophistication 用在动力系统上仍然失效。确定性系统 t 步后的状态，用「初态 + 规则 + t」就能描述，所以 Soph ≤ log₂ t + c，永远长不大[1]。修补办法是加资源限制，这就是 complextropy。

5　手算：两段式描述要多少位

一类常见的模型是「恰有 k 个 1 的 n 位串」。这个集合大小是 C(n, k)，下标要 log₂ C(n, k) 位。拖动滑块，对照第 2 课的 n·h(k/n)：两者很接近，这不是巧合，Shannon 熵就是「典型集合下标长度」的每位平均值。

练习 A：下标部分

x 是 100 位的串，恰好有 3 个 1，位置看起来是随机的。取 S = {恰有 3 个 1 的 100 位串}，下标部分需要多少位？保留 1 位小数。

再想一想：模型部分要说清楚 n = 100 和 k = 3，大约多少位？两段加起来，比 100 位短多少？

参考思路

写下 n 和 k 大约要 log₂ 100 + log₂ 3 ≈ 6.6 + 1.6 位，再加上一段固定外壳 c。总长约 17.3 + 8.2 + c ≈ 25.5 + c 位，远小于 100 位。这时模型部分只有 O(log n) 位，所以这个 x 的 sophistication 也很低。

6　回想测验

凭记忆作答，先别往上翻。

1. 长度为 n 的串中，满足 K(x) < n − k 的最多有多少个？

  1. 2ⁿ⁻ᵏ
  2. 2ⁿ − 2ᵏ
  3. 2ⁿ⁻ᵏ − 1
  4. n − k

长度 0 到 n−k−1 的程序一共 2ⁿ⁻ᵏ − 1 个，每个最多输出一个串。

2. Berry 式证明里，程序 Pm 的长度为什么只有 c + log₂ m？

  1. 它只需要存下数 m，其余部分（含假想的 Q）长度固定
  2. 它输出的 x 本身很短
  3. m 总是 2 的幂
  4. 它不需要停机

Pm 里唯一随 m 变化的是 m 的二进制写法，约 log₂ m 位。

3. 不变性定理说的是？

  1. 对所有 x，K(x) = |x|
  2. K(x) 与 x 的排列顺序无关
  3. 任何压缩器的输出长度都等于 K(x)
  4. 换一种通用语言，K(x) 最多相差一个与 x 无关的常数

常数就是用一种语言写另一种语言解释器的长度。

4. 均匀随机的 n 位串，sophistication 为什么很小？

  1. 因为它的 K(x) 很小
  2. 可以取 S = {0,1}ⁿ：模型只要 O(log n) 位，x 又是 S 的典型元素
  3. 因为条件 2 对随机串不成立
  4. 因为随机串不存在

随机串的 K 接近 n，但这 n 位全在下标那一段，模型部分几乎为零。

5. 第 3 节表格里，Rule 30 那一行 zlib 压不动，说明什么？

  1. 它的 K 接近 501 字节
  2. Rule 30 产生的是真正的随机串
  3. zlib 给的只是 K 的上界，可能离 K 很远
  4. zlib 有 bug

它的 K 不超过「规则 + 宽度 + 步数」的描述长度，只是 zlib 看不出来。

7　编程练习

练习 B：用 zlib 当 K 的替身

本题只用标准库，不需要 torch。写一个函数 C(b: bytes) -> int，返回 zlib.compress(b, 9) 的长度，然后验证三件事。

import random, zlib

rng = random.Random(0)
x = rng.randbytes(10_000)

assert C(x) >= len(x)                 # 随机串压不动
assert C(x + x) - C(x) < 200          # 重复一遍几乎不增加长度
assert C(bytes(10_000)) < 100         # 全 0 几乎压没了

y = rng.randbytes(100_000)
print(C(y + y) / C(y))                # 猜一猜，再运行

最后一行的比值是多少？为什么同样是「拼两遍」，10 000 字节时几乎不增加，100 000 字节时却几乎翻倍？

参考解答（写完再看） 
def C(b: bytes) -> int:
    return len(zlib.compress(b, 9))

我实测：C(x) = 10011，C(x + x) = 10163，C(bytes(10_000)) = 33；最后一行约 2.0（200 071 ⁄ 100 041）。

原因是 zlib（DEFLATE）只在最近 32 KiB 的窗口里找重复片段。第二遍 y 开头时，第一遍 y 的开头已经在 100 000 字节之前，超出窗口，看不见了。理想的 K 没有这种限制：K(yy) ≤ K(y) + c，因为「把 y 打印两遍」只多一段固定外壳。这又是替身和 K 之间的一道缝，第 7 课用压缩长度估复杂度时要记得。
