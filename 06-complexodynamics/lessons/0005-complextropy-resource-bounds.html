第 5 课 · 复杂动力学第一定律

Complextropy：为什么必须加资源限制

一个确定性系统的状态，总有一段只有 log t 位长的描述。这一课讲这个事实怎样让 K 和 sophistication 都失效，以及 Aaronson 怎样用「程序必须跑得快」把它堵上

第 4 课最后，sophistication 看上去正是我们要的东西：简单的串很低，随机的串也很低，只有「既不简单也不随机」的串才高。但 Aaronson 紧接着写道[1]：

Unfortunately, as we defined it above, sophistication still doesn't do the job. For deterministic systems, the problem is the same as the one pointed out earlier for Kolmogorov complexity: we can always describe the system's state after t time steps by specifying the initial state, the transition rule, and t. Therefore the sophistication can never exceed log(t) + c.

这一课先把这段话证明清楚，再看他的修正方案 complextropy：在定义里的两个地方加上计算效率的要求。

本课收获：你能证明 K(xₜ) ≤ log₂ t + O(log log t) + C，并由此说明不加限制的 K 和 Soph 都画不出「先升后降」。你能说出 complextropy 定义里的两处效率约束各自防的是什么。你还能解释为什么 gzip 这种压缩长度，可以当作资源受限复杂度的粗糙替身。

1　问题：确定性系统的状态太好描述了

拿第 1 课的 Rule 30 来说。从中间一个黑格出发，在无限长的直线上跑 t 步，第 t 行有 2t + 1 格，看上去是一片乱码。直觉上，描述它应该需要大约 2t + 1 位。但 Aaronson 指出[1]：

if the system happens to be deterministic, then mathematically, its state can always be specified by giving (1) the initial state, and (2) the number of steps t it's been run for. The former takes a constant number of bits to specify (independent of t), while the latter takes log(t) bits.

也就是说，只要说清楚「Rule 30，中间一个黑格，跑 t 步」，就能唯一确定这一行。这段描述里唯一随 t 变长的部分，就是 t 本身的二进制写法。

2　主证明：K(xₜ) 至多按 log t 增长

设定。初态 x₀ 和转移规则 R 都固定，跟 t 无关。xₜ = Rᵗ(x₀) 是跑 t 步后的状态。

构造程序 Pₜ。Pₜ 由四段拼成：（a）一个通用的模拟器，作用是「读入 x₀、R、t，把 R 作用 t 次，输出结果」；（b）x₀ 的编码；（c）R 的编码；（d）t 的编码。（a）（b）（c）三段跟 t 无关，长度合计记为常数 C。

t 怎么编码。程序必须知道 t 的编码在哪里结束，所以 t 的编码要自定界。一种做法是：设 t 的二进制有 ℓ = ⌊log₂ t⌋ + 1 位，先把 ℓ 的二进制每一位写两遍，再写一个分隔符 01，最后写 t 的 ℓ 位。读的时候两位两位地读，读到 01 就知道 ℓ 写完了，再往后读 ℓ 位就是 t。这段编码长 ℓ + 2⌈log₂(ℓ + 1)⌉ + 2 = log₂ t + O(log log t)。

结论。Pₜ 输出 xₜ，长度不超过 log₂ t + O(log log t) + C。K(xₜ) 是所有能输出 xₜ 的程序里最短的长度，所以

K(xₜ) ≤ log₂ t + O(log log t) + C∎

Aaronson 把右边简写成 log(t) + c，把 log log t 这一项也并进了「常数」里。两种写法的意思一样：K 随 t 至多按对数增长。

推论 1（熵）。如果用 K 当作熵，它的增长慢得离谱。t = 10⁶ 时，第 t 行有 2,000,001 位，K 的上界却只有大约 20 位再加一个常数。Aaronson 的原话是 "much slower than the linear or polynomial increase that we'd intuitively expect"[1]。

推论 2（sophistication）。按第 4 课的定义，Soph(x) 是所有满足条件的模型 S 中最小的 K(S)。取单元素集 S = {x}：x ∈ S 显然成立；条件 K(x|S) ≥ log₂|S| − c 的右边是 log₂ 1 − c = −c，也自动成立。所以 Soph(x) ≤ K({x}) ≤ K(x) + O(1)。代入主证明：

Soph(xₜ) ≤ log₂ t + O(log log t) + C

这条曲线也许会起伏，但它被一条几乎是平的天花板压着。像 notebook 第 3 节那样 50 × 50 的咖啡杯有 2500 格，就算跑一万亿步，log₂ t 也才约 40 位。这样的量没法在中间时刻变得「很大」，Sean Carroll 要的峰值也就画不出来。

换成随机系统也一样。Aaronson 接着论证：如果每一步带随机性，可以取 S(t) 为「t 步后所有可能的状态」组成的集合。描述 S(t) 只需要初态、随机规则和 t。只要 S(t) 上的分布是均匀的，用计数论证可知，实际状态几乎总是 S(t) 里的「普通」成员，所以 sophistication 仍然 "will almost never exceed log(t) + c"[1]。分布不均匀的情况他说需要更多技术论证，没有展开。2014 年的咖啡自动机论文用另一种取法给出了同样的结论：取 S 为「概率约等于 Pr[x] 的所有输出」，描述它只要 O(log n) 位[2]。

3　短描述的代价：要跑很久

上面的 Pₜ 很短，但它要真的把 t 步全模拟一遍。在无限直线的设定下，第 s 步要算 2s + 1 格，跑完 t 步总共要做 t² + 2t 次格子更新。拿它和 Aaronson 例子里的时间预算 n log₂ n 比一比（n = 2t + 1 是输出的长度）。拖动滑块看看：

t 从 7 开始，t² + 2t 就超过了 n log₂ n（t = 6 时是 48 对 48.1，刚好压线），并且差距越拉越大：t = 1000 时要做 1,002,000 次更新，预算只有约 21,944。一旦定义要求「程序必须在 n log n 时间内输出」，Pₜ 就不能用了，log t 的上界也随之失效。

注意这里只排除了 Pₜ 这一个程序，并没有证明不存在别的既短又快的程序。对 Rule 30 来说，能不能不逐步模拟就直接跳到第 t 行，本身是一个公开问题。Wolfram 2019 年为 Rule 30 设的悬赏题里，就有一道问计算中心列第 n 格是否至少要花大约 n 的计算量[4]。

练习 A：一万亿步要多少位？

t = 10¹² 时，⌈log₂ t⌉ 是多少？不用计算器，用 2¹⁰ ≈ 10³ 估算。

一个现成的「时间受限压缩器」：gzip

gzip（这里用 Python 的 zlib，压缩级别 9）只在线性时间里找局部重复，不会去猜「这是 Rule 30 跑了 t 步」。所以它可以看作一种非常严格的资源受限压缩器。我把无限直线上 Rule 30 的第 t 行按位打包后交给它压缩：

t25050010002000
行长 2t+1（位）501100120014001
zlib 压缩后（位）592109620964096
⌈log₂ t⌉（位，另加常数）891011

zlib 一点也没压下去，压缩后反而比按位打包的原始数据还多了大约 90 位的格式开销。在它看来，这一行就是随机的，压缩长度随 t 线性增长，正是我们期待的「熵」的样子。Aaronson 说的 "if we rule out sufficiently complex programs, we can again get our program size to increase with t at a polynomial rate"[1]，在这里看得很具体。

4　Aaronson 的修正：complextropy

先看熵这一半的修法。把 K 换成资源受限的 Kolmogorov 复杂度：在给定时间 T(n) 内输出 x 的最短程序的长度[1]。

Kᵀ(x) = min { |p| : 通用机运行 p，在 T(n) 步内输出 x }

候选程序变少了，最小值只会变大，所以总有 Kᵀ(x) ≥ K(x)。Aaronson 还说，具体加哪种资源限制不太重要，比如也可以限制为深度为 3 的电路，"as long as the bound is severe enough"。

复杂度这一半的修法，就是给 sophistication 也加上同样的限制。下面是他的原文定义[1]：

the number of bits in the shortest computer program that runs in n log(n) time, and that outputs a nearly-uniform sample from a set S such that (i) x ∈ S, and (ii) any computer program that outputs x in n log(n) time, given an oracle that provides independent, uniform samples from S, has at least log₂(|S|) − c bits, for some constant c.

拆开来看，定义里有两个程序：

角色要求对应 Soph 里的什么
采样器（被计长度的那个）n log n 时间内，输出 S 上近似均匀的样本描述 S 的程序，长度 K(S)
重构器（任何一个）n log n 时间内，可以向 S 要独立的均匀样本，要输出 x 至少需要 log₂|S| − c 位条件 K(x|S) ≥ log₂|S| − c：x 是 S 的普通成员

第二个条件的白话是：在任何高效算法看来，x 都像是从 S 里随机抽出来的一个样本。complextropy 就是满足条件的最短采样器的长度。n log n 只是一个例子，Aaronson 说也可以换成别的时间上界，或者常数深度电路之类的弱计算模型。

两处效率约束，缺一不可

Aaronson 特意强调，效率要求必须同时加在两个程序上[1]：

去掉对采样器的限制：又可以用「初态 + 规则 + t」去描述 S，回到第 2 节的论证，complextropy 不超过 log(t) + c，永远涨不起来。

去掉对重构器的限制：complextropy 会上升，但很可能一直升下去，不会回落。原因是受时间限制的采样器只能采到 S 的一个近似版本（"only a reasonable facsimile thereof"）。而不限时间的重构器可以利用 x 的特殊性质，用少于 log₂|S| − c 位就把 x 构造出来，使得这个近似版本的 S 不合格。

这就是本课标题的意思：不加资源限制，确定性动力学的 log t 短描述会把一切抹平。资源限制必须加，而且要两处都加。

5　猜想，以及能算的替身

Aaronson 的猜想是：加了两处效率约束的 complextropy 满足「复杂动力学第一定律」，初态小、中间大、混匀后又变小。他坦白说 "I don't yet know how to prove this conjecture"，并把它当作一个公开问题提出来：在咖啡杯这样的离散模型里，中间时刻的 complextropy 会不会变大？直觉是中间时刻要描述全黑、全白和混合区域之间不规则的边界，所以应该大[1]。

难点是 complextropy 几乎肯定没法计算，连近似都难。他建议的经验路线是："using something you can compute (e.g., the size of a gzip compressed file) as a rough-and-ready substitute for something you can't compute"[1]。2014 年他和 Carroll、Ouellette 的论文就是这么做的[2]：

  • 用表观复杂度（apparent complexity）K(f(x))：先用一个平滑函数 f 把 x 粗粒化，去掉「偶然的」细节，再用压缩长度近似 K。
  • 论文 §2.5 指出，这相当于把 sophistication 的模型固定为 Sf,x = {y : f(y) = f(x)}，也就是一种资源受限的 sophistication：不再在所有模型里取最小值，只看粗粒化给出的那一个。
  • 结果：粒子之间没有相互作用时，可以解析证明表观复杂度永远不会变大；有相互作用时，数值证据显示峰值大约与杯子的水平尺寸相当。

第 7 课会动手做这件事：用粗粒化加压缩长度，复现「先升后降」。第 6 课先把扩散本身用 conv2d 写清楚。

6　回想测验

凭记忆作答，先别往上翻。

1. 初态和规则都固定的确定性系统，第 t 步状态的 K(xₜ) 上界是？

  1. 2t + 1，等于状态长度
  2. t，与步数成正比
  3. log₂ t + O(log log t) + C
  4. 常数 C，与 t 无关

程序 = 模拟器 + x₀ + R + t。只有 t 的编码随 t 变长，自定界编码长度是 log₂ t + O(log log t)。

2. 为什么 Soph(x) ≤ K(x) + O(1)？

  1. 取 S = {x}，条件 K(x|S) ≥ log₂ 1 − c 自动成立，而 K({x}) ≤ K(x) + O(1)
  2. 取 S = {0,1}ⁿ，任何串都是它的普通成员
  3. 因为 sophistication 是可计算的
  4. 因为 K(x|S) 总是不小于 K(x)

单元素集是 x 永远可用的模型。选项 B 解释的是「随机串的 Soph 很小」，不是这个上界。

3. 如果 complextropy 只限制重构器、不限制采样器，会怎样？

  1. 会一直上升、不回落
  2. 又会被「初态 + 规则 + t」压到 log(t) + c 以下
  3. 变得可以计算
  4. 与 Shannon 熵相等

采样器不限时间，就可以从初态模拟 t 步得到 S，描述长度回到 log t 级别。

4. 如果只限制采样器、不限制重构器，Aaronson 预计会怎样？

  1. 恒为 0
  2. 与 K(x) 完全相等
  3. 先升后降，正好是想要的形状
  4. 会上升，但很可能一直升下去

快速采样器只能采到 S 的近似版本，不限时间的重构器能利用 x 的特殊性质，用少于 log₂|S| − c 位造出 x，于是那个 S 不合格。

5. 本课里 gzip 压缩长度扮演什么角色？

  1. K(x) 的精确值
  2. 一个时间受限的压缩器，可以计算，并且看不出「初态 + 规则 + t」这种描述
  3. Shannon 熵的另一种写法
  4. complextropy 的定义本身

Rule 30 第 2000 行有 4001 位，zlib 压缩后是 4096 位，完全没压下去，而理论上的描述只要约 11 位加一个常数。

7　编程练习

练习 B：描述 = (规则, 初态, t)

用纯 Python（不需要 torch）写 run(desc)：输入描述 desc = (rule, x0, t)，在周期边界上从 x0 模拟 t 步，返回第 t 行，以及总共做了多少次格子更新。规则号的用法同第 1 课：(rule >> (4*l + 2*c + r)) & 1。

验收（设置与 notebook 相同：100 格，中间一个 1）：

N = 100
x0 = [0] * N; x0[N // 2] = 1
row, ops = run((30, x0, 70))
assert sum(row) == 60            # 第 70 行有 60 个 1，和第 2 课的数据一致
assert ops == N * 70             # 每步更新 N 格，总量随 t 线性增长

import time
for t in [1000, 2000, 4000, 8000]:
    t0 = time.perf_counter(); run((30, x0, t))
    print(t, round(time.perf_counter() - t0, 3))   # 时间大致随 t 翻倍

做完再回答：如果时间预算是 N log₂ N 次更新（N = 100 时约 664 次），这个描述最多能跑几步还算「高效」？

参考解答（写完再看） 
def step(row, rule):
    n = len(row)
    return [(rule >> (4*row[i-1] + 2*row[i] + row[(i+1) % n])) & 1 for i in range(n)]

def run(desc):
    """按描述 (rule, x0, t) 从头模拟，返回第 t 行和格子更新次数。"""
    rule, x0, t = desc
    row, updates = list(x0), 0
    for _ in range(t):
        row = step(row, rule)
        updates += len(row)
    return row, updates

row[i-1] 在 i = 0 时取到 row[-1]，(i+1) % n 在末尾绕回 0，这就是第 1 课 torch.roll 的周期边界。描述本身很短：规则 8 位，初态「中间一个 1」只要 O(log N) 位，t 只要 log₂ t 位。但运行代价是 N·t。预算 N log₂ N 只允许 t ≤ log₂ N ≈ 6.64，也就是最多 6 步。这台机器上 t 从 1000 翻倍到 8000，耗时大约是 0.005 → 0.011 → 0.020 → 0.035 秒，基本是线性的。
