从数字 30 到一行 PyTorch

规则号怎样编码一张规则表，以及 torch.roll 怎样一次更新所有格子

Aaronson 的问题是：为什么在一个封闭系统里，熵只增不减，「有趣的结构」却先出现再消失[4]？notebook 用 Rule 30 当第一个实验对象，因为它规则极简，演化出的图案却很复杂[1]。后面每一节测熵、测复杂度，都要先把这张图生成出来。所以第一步是吃透 notebook 第 1 节里这一行：

history[t] = rule_func(torch.roll(prev, 1), prev, torch.roll(prev, -1))

本课收获：给你任意一个规则号 n ∈ [0, 255]，你能写出它的规则表，并能写出 PyTorch 函数 make_rule(n)，直接替换 notebook 里的 rule_30 使用。

↑ Rule 30 从中间一个黑格出发演化 30 步。这张图由本页的 assets/ca.js 实时算出，用的是本课讲的同一条规则。

1　规则号就是规则表

每个格子下一刻的状态，只取决于它自己 c 和左右邻居 l, r。三个 0/1 一共有 2³ = 8 种组合。把每种组合 (l, c, r) 当成一个三位二进制数：

k = 4l + 2c + r　　新状态 = 规则号 n 的第 k 位 = (n >> k) & 1

这就是 Wolfram 的编号约定：把规则号写成二进制，各位依次给出 8 种情况的新颜色[2]。30 = 16 + 8 + 4 + 2，所以第 4、3、2、1 位是 1，其余是 0：

邻域 l c r111110101100011010001000
k76543210
新状态（30 的第 k 位）00011110

表的第三行从左往右读就是 00011110₂ = 30，与 Wikipedia 给出的规则表一致[1]。注意 notebook 的表也是从 111 排到 000，原因就在这里：这样排，输出那一列从上往下读刚好是规则号的二进制。

2　推导布尔式 l ⊕ (c ∨ r)

notebook 直接给出 f(l,c,r) = l ⊕ (c ∨ r)，没有推导。下面用分情况讨论证明它和上表完全等价。

情况一：c ∨ r = 0，即 c = r = 0。对应邻域 100 和 000，查表得新状态分别为 1 和 0，正好等于 l。而 l ⊕ 0 = l。✓

情况二：c ∨ r = 1。对应剩下的 6 种邻域：l = 1 时（111, 110, 101）新状态全是 0，l = 0 时（011, 010, 001）全是 1，正好等于 ¬l。而 l ⊕ 1 = ¬l。✓

两种情况覆盖了全部 8 个邻域，所以两种写法处处相等。∎

这条证明还给出一句直白的读法：中间和右边都是空的，就照抄左邻居；只要有一个不空，就把左邻居取反。Wikipedia 写作 p xor (q or r)，是同一个式子[1]。

3　torch.roll：一次拿到所有格子的左邻居

官方文档对 torch.roll 的说明是：把张量沿某一维滚动，移出最后一个位置的元素会从第一个位置重新进入[3]。

x = torch.tensor([1, 2, 3, 4, 5])
torch.roll(x, 1)    # tensor([5, 1, 2, 3, 4])
torch.roll(x, -1)   # tensor([2, 3, 4, 5, 1])

关键是方向。roll(x, 1) 把内容往右挪一格，于是新张量第 i 位放的是原来第 i−1 位：

torch.roll(x, 1)[i] = x[i − 1]　→　每个格子的左邻居
torch.roll(x, −1)[i] = x[i + 1]　→　每个格子的右邻居

「往右挪」得到的却是「左邻居」，这是最容易记反的地方。另外，下标 0 的左邻居会绕回 x[n−1]，这就是 notebook 说的周期边界：100 个格子首尾相接，排成一个环。

三个张量 left, center, right 形状相同（都是 (size,)），^ 和 | 对它们逐元素运算。所以 rule_30(left, center, right) 一次就算完一整行，不用写 for 循环遍历格子。

练习 C（编程）：make_rule(n)

在 notebook 第 1.3 节之后新开一个单元格，写一个函数 make_rule(n)。它返回一个规则函数，签名与 rule_30(left, center, right) 相同，可以直接传给 evolve_ca。要求：不用 if，也不用循环遍历格子。

提示：先把 8 个输出做成长度为 8 的张量 table，再想想 4*left + 2*center + right 这个张量能拿来干什么。

验收：

assert torch.equal(evolve_ca(initial, 100, make_rule(30)),
                   evolve_ca(initial, 100, rule_30))
plt.imshow(evolve_ca(initial, 100, make_rule(90)), cmap='binary')  # 应看到谢尔宾斯基三角
参考解答（写完再看） 
def make_rule(n: int) -> Callable:
    table = torch.tensor([(n >> k) & 1 for k in range(8)])  # table[k] = 第 k 位
    def rule(left, center, right):
        return table[4 * left + 2 * center + right]          # 用整数张量做下标查表
    return rule

4*left + 2*center + right 是一个和整行同形状的整数张量，每个元素就是该格的 k。用它去索引 table，会得到同形状的结果，整行一次查完。这种做法叫「高级索引」，后面实现 embedding 时还会遇到。
