第 3 课 · 复杂动力学第一定律

度量的陷阱：同一张图，三种读数

转换次数、单格熵、压缩长度各自看见什么、看不见什么，以及 notebook 的「先升后降」从哪来

notebook 第 2 节用下面这个函数量「复杂度」，再把结果画在「熵」旁边。第 4.1 节「對比熵與複雜度」的表据此写下：

def measure_spatial_complexity(state):
    """相鄰元素發生 0/1 轉換的次數。"""
    transitions = torch.sum(torch.abs(torch.diff(state.float())))
    return int(transitions.item())

熵：「永遠增加 ↗」　複雜度：「先升後降 ∧」——notebook 第 4.1 节

可是把 notebook 自己的数字拿出来看：100 个格子、中间一个 1、Rule 30 演化 100 步，转换次数在 t = 0, 10, …, 90 时依次是

2, 12, 18, 34, 34, 52, 47, 50, 49, 51

最大值 58 出现在 t = 77，之后在 50 附近波动，没有回落。notebook 第 2 节画完图打印的观察其实写的是「複雜度先升後（趨於穩定）」，只是到了 4.1 的总结表变成了「先升後降」。这节课不急着判谁对，先把「度量」这件事拆开：一个数字测的是什么，决定了它能画出什么曲线。

本课收获：你能对任意一行 0/1 状态说出三种度量的值和盲点；能用期望的线性性证明随机行的平均转换次数是 (N−1)/2，用计数论证证明绝大多数串无法压缩；能用 torch.diff(dim=1) 一次算完整段演化的转换次数，并写出一个压缩长度函数。

1　三种度量

度量定义notebook 里
单格熵 H只看 1 的比例 p，算 h(p)（第 2 课）measure_entropy
转换次数 T相邻两格取值不同的对数，T = Σᵢ |xᵢ₊₁ − xᵢ|，最多 N − 1measure_spatial_complexity
压缩长度 Z把整行交给 zlib 压缩，输出的字节数没有。本课新加

三者的「视野」不同。H 只看计数，完全不看位置；T 只看相邻两格，是一个局部的、长度为 2 的窗口；Z 交给压缩器，压缩器会去找任意距离上的重复片段。下面这一行可以直接试：点格子、按「打乱」和「排序」，看 H 和 T 怎么变。

练习 A：同一组 0 和 1，两种读数

先按「随机」，再反复按「打乱」：H 一动不动，T 跳来跳去。再按「排序」：T 变成 1 或 0。H 对「重新排列」不变，T 对它极其敏感。

数相邻两格颜色变化的地方。notebook 用的 torch.diff 不绕回首尾，所以 16 格只有 15 对。

2　同一组状态，三张成绩单

下表的每一行都是 1000 个格子。压缩长度的算法是：每 8 格打包成 1 个字节（共 125 字节），再用 Python 的 zlib.compress(…, 9) 压缩，数输出的字节数。「随机」是一条用伪随机数生成的行；Rule 30 一行取宽 1000、中间一个 1、演化到 t = 499 的那一行。所有数字我都用纯 Python 算过。

逐列读：

  • 单格熵把「交替」「左半」「随机」「Rule 30」全判成约 1 bit。它分不出有规律和没规律，因为它根本不看位置。
  • 转换次数给「交替 0101」打了满分 999，比随机行还高近一倍。可交替串是最单调乏味的图案之一。T 把「变化多」误当成「结构多」。
  • 压缩长度是三者里唯一把「交替」和「随机」分开的：交替串 12 字节，随机串 136 字节。它看的是「能不能用更短的方式说出来」，这是对的方向。

但压缩长度也有两个问题。第一，它给随机行打了最高分。随机串没有任何「有趣的结构」，可它最难压缩。所以 Z 量的更像熵，不像复杂度：Aaronson 等人的咖啡论文正是这么用的，他们把压缩长度当作熵的估计，而不是复杂度[2]。随机不等于复杂，notebook 4.1 节的「關鍵洞見」里也写了「隨機 ≠ 複雜」，可它选的度量并没有做到这一点。

第二，Rule 30 那一行和随机行压出来一样长（136 字节，比原始的 125 字节还多）。可它其实能用很短的程序生成：「从中间一个 1 出发，按 Rule 30 演化 499 步」。zlib 找的是重复片段，看不出这种规律。所以压缩长度只是「最短描述长度」的一个上界，而且可以很松。这个「最短描述长度」就是第 4 课的 Kolmogorov 复杂度 K(x)。

短串要小心 zlib 的固定开销

zlib 的输出包含 2 字节头部和 4 字节校验和，压缩一个空串都要 8 字节。上表全 0 的 125 字节压到 12 字节，其中一大半是这些开销。notebook 的 100 格一行打包后只有 13 字节，压缩后反而是 15 到 22 字节，信号完全被开销淹没。所以本课把宽度加到了 1000。要用压缩长度做实验，串一定要够长，或者把多行拼起来一起压。

3　两个推导

随机行的平均转换次数是 (N − 1)/2

设 N 个格子独立、各以 1/2 的概率取 1。对每一对相邻格定义指示变量 Iᵢ = 1 当且仅当 xᵢ ≠ xᵢ₊₁，于是 T = I₁ + … + IN−1。

两格不同有两种情况 (0,1) 和 (1,0)，概率各 1/4，所以 E[Iᵢ] = P(xᵢ ≠ xᵢ₊₁) = 1/2。

期望是线性的，不需要 Iᵢ 之间相互独立（相邻两对共用一个格子，它们确实不独立）：

E[T] = Σᵢ E[Iᵢ] = (N − 1)/2。∎

N = 1000 时是 499.5。我生成了 200 条随机行，T 的平均值是 500.2，与理论值吻合。把 1/2 换成一般的 p，同样的推导给出 E[T] = 2p(1 − p)(N − 1)。

这个结果说明：在 T 看来，随机行的「复杂度」稳定在最大值的一半左右。Rule 30 演化到后期，行的统计性质越来越接近随机，所以 T 停在 50 附近的平台上（100 格时 (100 − 1)/2 = 49.5），不会回落。notebook 的「先升后降」不是 Rule 30 的性质，而是读图读出来的。

绝大多数串无法压缩

固定任意一个无损压缩方案，即一个解压程序 D：每个压缩串 y 解压出唯一的 D(y)。问：长度为 n 的二进制串里，有多少个能被压到长度小于 n − k？

长度小于 n − k 的二进制串一共有 1 + 2 + 4 + … + 2n−k−1 = 2n−k − 1 个。每个最多解压出一个串，所以能被压到这么短的串少于 2n−k 个。

长度为 n 的串一共 2n 个，所以它们所占比例 < 2n−k / 2n = 2−k。∎

k = 10 时，比例不到千分之一。这个论证对任何压缩器都成立，包括理论上最好的那个，所以它也适用于 Kolmogorov 复杂度：长度为 n、复杂度小于 n − c 的串所占比例小于 2−c[3]。随机行压不动是必然的，不是 zlib 不够好。

4　Rule 30 上，三种度量都只升不降

下图由本页实时算出，设置与 notebook 相同（100 格，100 步）。两条线都除以了各自的理论最大值（H 最大 1 bit，T 最大 N − 1 = 99），放在同一个 [0, 1] 坐标里。

两条线走势相同：先爬升，再在平台上波动，都没有回落。转换次数的平台在 0.5 附近，正是上一节推出的随机行期望值。换成压缩长度也一样：宽 1000 时，t = 0, 50, …, 450 的压缩长度依次是 16, 28, 42, 56, 68, 81, 93, 108, 121, 134 字节，一路上升，到 t = 499 是 136 字节。

所以三种度量在 Rule 30 上的结论一致：只升不降。要看到「先升后降」，需要两样东西同时满足：

  1. 系统会走向平衡态，平衡态本身是「简单」的（比如咖啡和奶油完全混匀，一片均匀的浅棕色）。
  2. 度量对随机给低分。H、T、Z 都对随机给高分，所以都不行。第 4 课的 sophistication 和第 7 课的「粗粒化后再压缩」就是为了解决这一点。

5　回想测验

凭记忆作答，先别往上翻。

1. 把一行 0/1 随机打乱顺序，以下哪个量一定不变？

  1. 转换次数 T
  2. zlib 压缩长度 Z
  3. 单格熵 H
  4. 三个都会变

H 只依赖 1 的个数，打乱不改变计数。T 和 Z 都依赖位置。

2. 1000 格的「交替 0101…」，三种度量里哪个会给它打出最高分（相对其他状态）？

  1. 转换次数 T，取最大值 999
  2. 压缩长度 Z，因为它变化最频繁
  3. 单格熵 H，因为只有它达到 1
  4. 都不会，它在每种度量下都是最低

交替串每一对相邻格都不同，T = N − 1 = 999。但它压缩后只有 12 字节，和全 0 一样短。

3. 证明 E[T] = (N − 1)/2 时，为什么不需要 Iᵢ 相互独立？

  1. 因为相邻的 Iᵢ 确实相互独立
  2. 因为 N 足够大时依赖可以忽略
  3. 因为 T 服从二项分布
  4. 因为期望的线性性对任何随机变量都成立

E[X + Y] = E[X] + E[Y] 不需要独立性。方差才需要考虑相关性。

4. 长度为 n 的二进制串中，能被某个固定的无损压缩器压到少于 n − 10 位的，比例最多是？

  1. 1/10
  2. 不到 2−10，约千分之一
  3. 一半
  4. 取决于压缩器有多好

短于 n − 10 位的串一共不到 2n−10 个，每个最多对应一个原串。这个上界对任何压缩器都成立。

5. Rule 30 第 499 步那一行，zlib 压缩后和随机行一样长。这说明什么？

  1. Rule 30 的输出真的是随机的，不可能用短程序生成
  2. zlib 压缩出了错
  3. 压缩长度只是最短描述长度的上界，zlib 看不出「按规则演化」这种规律
  4. 应该把 zlib 的压缩级别从 9 调到 1

「宽 1000，中间一个 1，按 Rule 30 演化 499 步」就是一个很短的完整描述。zlib 只会找重复片段，找不到这条描述。

6　编程练习

练习 C：一次算完整段演化的转换次数，再加上压缩长度

(1) notebook 的 measure_complexity_over_time 用循环逐行调用。写一个 transitions_over_time(history)：输入形状 (T, N) 的 0/1 张量，返回形状 (T,)，不写循环。

提示：torch.diff(x, dim=1) 沿第 1 维做相邻差分，(T, N) 变成 (T, N−1)。第 1 维变短了一格，和第 2 课的 mean(dim=1) 把这一维整个消掉不一样。

(2) 写一个 compressed_len(row)：输入一行 0/1 张量，每 8 格打包成 1 个字节，返回 zlib.compress(…, 9) 的字节数。

提示：先 .numpy() 转成 NumPy 数组，np.packbits 会把 0/1 数组每 8 个打成一个 uint8，长度不是 8 的倍数时末尾补 0。再 .tobytes() 交给 zlib。

验收：

T = transitions_over_time(evolution)
assert T.shape == (100,)
assert torch.equal(T.float(), measure_complexity_over_time(evolution))
assert T.argmax().item() == 77 and T.max().item() == 58

N = 1000
alt = torch.arange(N) % 2
assert compressed_len(alt) == 12
assert compressed_len(torch.zeros(N, dtype=torch.long)) == 12
assert compressed_len(torch.randint(0, 2, (N,))) >= 125   # 随机行几乎必然压不动
参考解答（写完再看） 
import zlib
import numpy as np

def transitions_over_time(history: torch.Tensor) -> torch.Tensor:
    return torch.diff(history, dim=1).abs().sum(dim=1)   # (T, N) → (T, N−1) → (T,)

def compressed_len(row: torch.Tensor) -> int:
    packed = np.packbits(row.numpy().astype(np.uint8))   # 每 8 格 → 1 字节
    return len(zlib.compress(packed.tobytes(), 9))

torch.diff 对整数张量也能用，所以不必像 notebook 那样先 .float()。abs() 把 −1（1→0）和 +1（0→1）都变成 1。

最后一条 assert 用到了第 3 节的计数论证：随机的 1000 位要压到 124 字节（992 位）以内，概率不到约 2−8。这还没算 zlib 至少 6 字节的头部和校验和，算上以后几乎不可能发生。

验收里的 12 字节是我用纯 Python 的 zlib 算的。不同版本的 zlib 输出可能差一两个字节，如果对不上，先打印出来看看再说。
