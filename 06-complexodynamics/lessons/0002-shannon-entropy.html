Shannon 熵：为什么最多 1 bit

从「平均惊讶度」推出二元熵的最大值，再逐行读懂 notebook 的 measure_entropy

Aaronson 的「第一定律」有两半：熵单调增，复杂度先升后降[4]。notebook 用 Shannon 熵量第一半，画出一条从 0 爬到 1 的曲线，旁边还画了一条红色虚线，标着「理论最大熵」。这节课回答两个问题：这条线为什么正好在 1？notebook 算出来的这个数，到底在量什么？

def measure_entropy(state):
    _unique, counts = torch.unique(state, return_counts=True)
    probs = counts.float() / len(state)
    entropy = -torch.sum(probs * torch.log2(probs + 1e-10))
    return entropy.item()

本课收获：你能用求导证明二元熵在 p = 1/2 处取最大值 1 bit，用 Jensen 不等式证明一般情形 H ≤ log₂ n，并能不写循环、一行算出整段演化每一步的熵。

1　定义：熵是平均惊讶度

一个结果发生的概率是 p，看到它时的「惊讶度」定义为 −log₂ p。必然发生的事（p = 1）惊讶度是 0；概率越小，惊讶度越大。一个分布的熵，就是惊讶度的期望值[1]：

H(p₁, …, pₙ) = −Σᵢ pᵢ log₂ pᵢ　　单位：bit

只有两种结果（0 和 1）时，设取 1 的概率为 p，熵就是一个单变量函数，叫二元熵函数：

h(p) = −p log₂ p − (1 − p) log₂(1 − p)

拖动下面的滑块：p 很小时，「看到 1」惊讶度很大，但它很少发生；「看到 0」几乎不惊讶。两项加权平均后，熵反而很小。

还有一个边界问题：p = 0 时 log₂ 0 没有定义。约定 0 · log 0 = 0，理由是极限：

limp→0⁺ p ln p = lim ln p ⁄ (1/p)，分子分母都趋于无穷，用洛必达法则得 lim (1/p) ⁄ (−1/p²) = lim (−p) = 0。∎

直观的说法是：不会发生的结果，对平均惊讶度没有贡献。第 4 节会看到，代码里有三种写法来处理这个约定。

2　推导：二元熵在 p = 1/2 取最大值 1

先换成自然对数，log₂ x = ln x ⁄ ln 2，再用 (p ln p)′ = ln p + 1。

一阶导数。h′(p) = −(1/ln 2)·[(ln p + 1) − (ln(1−p) + 1)] = log₂((1 − p) ⁄ p)。两个 +1 正好抵消。

驻点。h′(p) = 0 ⇔ (1 − p)/p = 1 ⇔ p = 1/2。而且 p < 1/2 时 h′ > 0，p > 1/2 时 h′ < 0，所以先增后减。

二阶导数。h″(p) = −1 ⁄ (ln 2 · p(1 − p)) < 0，在 (0, 1) 上处处成立，h 严格凹，驻点就是唯一的最大值点。

代值。h(1/2) = −½ log₂ ½ − ½ log₂ ½ = ½ + ½ = 1。端点 h(0) = h(1) = 0。∎

顺带得到对称性 h(p) = h(1 − p)：把 0 和 1 的名字对调，熵不变。notebook 那条红色虚线画在 1 上，依据就是这个结论。

推广：n 种结果时 H ≤ log₂ n

状态不止两种时（比如 notebook 第 3 节的咖啡实验，把浓度分成 20 个区间），上界是 log₂ n。用 Jensen 不等式一行就能证明：log₂ 是凹函数，所以「先取对数再平均」不超过「先平均再取对数」[2]。

只对 pᵢ > 0 的项求和（p = 0 的项按约定是 0）：

H = Σ pᵢ log₂(1/pᵢ) ≤ log₂(Σ pᵢ · (1/pᵢ)) = log₂ m ≤ log₂ n

其中 m 是概率不为零的结果个数。第一个「≤」是 Jensen，取等号当且仅当所有 1/pᵢ 相等；第二个取等号当且仅当 m = n。两个合起来：当且仅当分布均匀，H = log₂ n。∎

n = 2 时这就是上面求导的结论。n = 20 时上界是 log₂ 20 ≈ 4.32 bit，后面看咖啡实验的熵曲线时会用到。

4　逐行读 measure_entropy

第一行：torch.unique(state, return_counts=True)。返回两个张量：排好序的不同取值，以及每个取值出现的次数[3]。两个张量形状都是 (m,)，m 是 state 里实际出现过的不同取值个数。

torch.unique(torch.tensor([0, 1, 1, 0, 1]), return_counts=True)
# (tensor([0, 1]), tensor([2, 3]))
torch.unique(torch.zeros(5, dtype=torch.long), return_counts=True)
# (tensor([0]), tensor([5]))        ← 没出现的 1 根本不会列出来

第二行：counts.float() / len(state)。counts 是整数张量，先转成浮点再除。len(state) 是第 0 维的长度，这里就是格子数 100。

第三行：probs * torch.log2(probs + 1e-10)。逐元素相乘再求和，就是定义式。那个 1e-10 是防 log₂ 0 的保险。但这里它其实用不上：unique 只列出现过的取值，counts 不会是 0，probs 也就不会是 0。它也几乎不改变结果：float32 的精度大约是 10⁻⁷，1 + 1e-10 在 float32 里就等于 1。

处理 0 · log 0 = 0 一共有三种写法，notebook 用了前两种：

写法出现在哪要点
log2(p + 1e-10)measure_entropy加一个小数绕开 0。简单，但结果有极小偏差
p = p[p > 0]measure_spatial_entropy布尔掩码，把零概率项直接丢掉。histc 会产生空区间，所以必须处理
torch.special.xlogy(p, p)本课练习 C算 p·ln p，p = 0 处直接返回 0，形状不变，可以批量算[3]

如果想要固定长度的计数（没出现的值也记 0），用 torch.bincount(state, minlength=2)：对全 0 的行它返回 tensor([5, 0])，而不是 unique 的 tensor([5])。咖啡实验里的浓度是连续值，要用 torch.histc(x, bins=20, min=0, max=1) 先分成 20 个区间再计数。它只接受浮点张量，区间外的值不计入[3]。

5　notebook 的熵在量什么

下面这条曲线由本页实时算出：Rule 30，100 个格子，中间一个 1，演化 100 步，每一行算一次熵。设置与 notebook 第 2 节相同。

具体数值（我用纯 Python 核对过）：t = 0 时只有 1 个 1，p = 0.01，H ≈ 0.081 bit；t = 10 时 H ≈ 0.500；t = 35 时第一次超过 0.99；t = 60 以后一直在 0.958 到 1.000 之间小幅波动。整体趋势是上升，最后贴近上界 1。但仔细看曲线是锯齿状的，相邻两步经常一涨一跌，所以严格说它并不单调。

但这个熵只依赖 1 的个数。公式里只有 p，没有任何格子的位置。所以把一行任意打乱，熵都不变。用下面这一行试试：

练习 B：造一行熵为 1、但看起来最有规律的状态

点格子翻转。可以先试几个预设，再自己造。

想一想：「交替 0101」和「随机」的熵都是 1 bit；「左半全 1」也是 1 bit。一个分不出这三种状态的数，能拿来描述 Aaronson 说的「结构」吗？

准确的说法是：notebook 量的是单个格子取值的边缘分布的熵，即随便抽一格，它是 0 还是 1 的不确定性。它不是整行状态的熵，也看不到格子之间的关系。这正是第 3 课的主题：换成「转换次数」或「压缩长度」，各自能看到什么、看不到什么。

6　回想测验

凭记忆作答，先别往上翻。

1. 二元熵函数的导数 h′(p) 等于？

  1. −log₂ p
  2. log₂((1 − p)/p)
  3. log₂(p(1 − p))
  4. 1 − 2p

(p ln p)′ = ln p + 1，两项的 +1 抵消，剩 (ln(1−p) − ln p)/ln 2。

2. 有 n 种结果的分布，H = log₂ n 的充要条件是？

  1. 某一个 pᵢ = 1
  2. 所有 pᵢ > 0
  3. n 是 2 的幂
  4. 分布是均匀的

Jensen 取等号要求所有 1/pᵢ 相等，第二个不等式取等号要求没有零概率项，两个合起来就是均匀分布。

3. 对 100 个格子全是 0 的行，torch.unique(state, return_counts=True) 返回的 counts 是？

  1. tensor([100])
  2. tensor([100, 0])
  3. tensor([0, 100])
  4. tensor([])

unique 只列出现过的值。想要 [100, 0] 这种固定长度，用 bincount(state, minlength=2)。

4. measure_entropy 里的 + 1e-10，实际作用是？

  1. 防止 counts 为 0 时出现 log 0
  2. 让熵的上界从 1 变成略大于 1
  3. 基本没作用：unique 不会给出 0 概率，float32 里 1 + 1e-10 又等于 1
  4. 把单位从 nat 换成 bit

真正需要处理 0 概率的是 histc 那个函数，它用了布尔掩码 p[p > 0]。

5. 100 格的「交替 0101…」和一条随机行，notebook 的熵分别约为？

  1. 0 和 1
  2. 1 和 1
  3. 1 和 0.5
  4. 0.5 和 1

交替行恰好 50 个 1，p = 1/2，H = 1；随机行的 p 也接近 1/2。这个熵只看 p，分不出两者。

7　编程练习

练习 C：一行算出整段演化的熵

notebook 的 measure_entropy_over_time 用 Python 循环逐行调用 measure_entropy。写一个 entropy_over_time(history)：输入形状 (T, N) 的 0/1 张量，返回形状 (T,) 的熵。要求不写循环。

提示：

  • history.float().mean(dim=1) 沿第 1 维（每一行）求平均，正好是每一行的 p，形状 (T,)。
  • torch.special.xlogy(p, p) 算 p·ln p，p = 0 时返回 0。结果是自然对数，要换成 bit。

验收：

H = entropy_over_time(evolution)
assert H.shape == (100,)
assert torch.allclose(H, measure_entropy_over_time(evolution), atol=1e-5)
print((H > 0.99).nonzero()[0].item())   # 应该是 35
参考解答（写完再看） 
import math

def entropy_over_time(history: torch.Tensor) -> torch.Tensor:
    p1 = history.float().mean(dim=1)              # (T,)  每一行 1 的比例
    p = torch.stack([p1, 1 - p1], dim=1)          # (T, 2) 每一行的分布
    return -torch.special.xlogy(p, p).sum(dim=1) / math.log(2)

torch.stack(..., dim=1) 在第 1 维把两个 (T,) 拼成 (T, 2)，每一行是一个分布 (p, 1−p)。sum(dim=1) 再把每一行的两项加起来。dim 这个参数后面几乎每节课都会用：沿哪一维做运算，那一维就被消掉。
