第 7 课 · 复杂动力学第一定律

咖啡自动机：让复杂度先升后降

粗粒化加压缩长度，复现 Aaronson、Carroll、Ouellette 2014 年的实验，再拿它检验 notebook 的连续扩散

notebook 的总结图写着「熵永遠增加；複雜度先升後降」，但前面几课已经看到，它用来画图的两个度量（单格熵、转换次数）都撑不起这句话。Aaronson 自己也知道博客里只是猜想。三年后，他和 Sean Carroll、Lauren Ouellette 写了一篇论文，第一次把这个猜想做成可以跑的实验[1]。用的度量叫表观复杂度（apparent complexity）：先把状态「抹模糊」，去掉随机细节，再看剩下的东西有多难描述[1, §2.1]。

表观复杂度 = K(f(x)) ≈ gzip(粗粒化并分档后的 x) 的字节数　　熵 ≈ gzip(x) 的字节数

本课收获：你能自己写出咖啡自动机，用 F.avg_pool2d 做粗粒化，跑出「熵一路升、表观复杂度先升后降」的两条曲线；能推导窗口要多大才能压住随机噪声；还能说清 notebook 的连续扩散为什么连「熵」都会先升后降。

1　论文的实验设置

状态是一个 n×n 的 0/1 数组，1 是奶油，0 是咖啡。初态上半全是 1，下半全是 0[1, §3]。论文比较了两种演化规则：

模型规则特点
交互模型每一步随机选一对上下或左右相邻、取值不同的格子，交换它们一格只能放一个粒子，粒子互相挡路
非交互模型每一步每个奶油粒子各自往随机方向走一格，一格可以叠很多粒子每个粒子独立做随机游走，容易做理论分析

度量分两步[1, §5.1]：

  1. 粗粒化：每一格换成以它为中心的 g×g 窗口的平均值（g 叫 grain size）。窗口伸出边界时，只平均落在数组里的格子。
  2. 分档：把平均值分成三档，接近 0 是「咖啡」，接近 1 是「奶油」，接近 0.5 是「混合」。分档后的数组用 gzip 压缩，字节数就是复杂度的估计；原始细粒度数组的压缩字节数是熵的估计。

论文里能看出几次尝试：他们先试过 OSCR 算法和「粗粒化 + 差分」的两段式编码，都因为噪声或伪影放弃了，最后才用上面这种最直接的做法[1, §4]。

2　亲手跑一次

下面的模拟在你的浏览器里实时运行：n = 48，交互模型，每 25 万步量一次。压缩用浏览器自带的 deflate，与 gzip、Python 的 zlib 是同一种算法。点「开始」，几秒钟就能跑完 600 万步。

有一处实现细节和论文不同：论文每一步从「取值不同的相邻对」里均匀挑一对，我的写法是随机挑一个格子和一个方向，两边相同或撞到杯壁就作废。每一对相邻格子都正好对应两个（格子, 方向）组合，所以只看真正发生的交换，挑中每一对的概率仍然相等，和论文的规则一样，只是有些步数空转掉了。曲线形状不受影响，只是时间轴被拉长了。

熵一路上升，最后停在 430 字节左右，和一张完全随机的 48×48 0/1 数组压缩后的大小（我试了 5 张，420 到 439 字节）没有区别。复杂度从 31 爬到 219，再回落到 30 上下：250 万步以后都在 27 到 65 之间。换种子 1、2、3 再跑，峰值分别是 204、193、228，出现在 100 万到 125 万步之间，600 万步时回落到 40、28、36。先升后降的形状每次都在。

初态和终态为什么都简单？初态粗粒化后是「上半奶油、下半咖啡，中间一条过渡带」，终态是「整张都是混合」，各用一句话就能说完。中间那段，奶油像手指一样伸进咖啡，粗粒化后三档的边界弯弯曲曲，要逐段描述，压缩不掉。论文还发现，复杂度峰值大致和边长 n 成正比，峰值出现的时间随 n 按二次曲线增长[1, §5.2]。

3　推导：窗口要多大才压得住噪声

在模拟里把窗口改成 3×3 试试：终态的「复杂度」降不下来。原因是完全混合以后，每个窗口里 1 的比例只是平均等于 1/2，实际会上下抖动。抖动一旦越过 1/3 或 2/3，这一格就会被分到「咖啡」或「奶油」档，留下一个噪点，gzip 就得花字节去记它。

设定。完全混合时，把窗口里的 m = w² 个格子近似看成独立的 Bernoulli(1/2)。总数守恒会带来一点负相关，这里先忽略。

均值和方差。窗口平均 X̄ = (1/m)Σ Xᵢ，E[X̄] = 1/2，Var[X̄] = (1/m)·(1/2)(1/2) = 1/(4w²)，标准差 σ = 1/(2w)。窗口边长每翻一倍，抖动减半。

出档概率。中间档是 [1/3, 2/3)，离开它需要 |X̄ − 1/2| ≥ 1/6，也就是偏离 (1/6)/σ = w/3 个标准差。由中心极限定理，

P(出档) ≈ 2Φ(−w/3)

其中 Φ 是标准正态的累积分布函数。∎

用 Φ(−1) ≈ 0.1587、Φ(−5/3) ≈ 0.0478、Φ(−3) ≈ 0.00135 代入，再和模拟对照。模拟数据取种子 0、600 万步时的终态，只统计窗口完整落在数组内的格子：

窗口 w1（不粗粒化）35913
理论出档概率 2Φ(−w/3)—31.7%9.6%0.27%≈ 0
模拟中实际出档比例100%36.0%11.7%0.19%0
终态「复杂度」（字节）4294372383825

w = 1 时完全没有粗粒化，「复杂度」就等于熵；w = 3 时噪点太多，终态和熵一样大，先升后降完全看不出来；w = 9 时只剩约 0.2% 的噪点，曲线才回落。作为对照，一整张全是「混合」档的 48×48 数组压缩后是 25 字节。

论文附录给了这个论证的严格版本：用 Chernoff 界控制单个 L×L 块偏离期望的概率，再对全部 n² 个块取并集界。结论是只要 L ≫ G√(3 ln(2n²))（G 是灰度档数），所有块同时不出错的概率就很高[1, 附录]。n = 48、G = 3 时右边约等于 15。这个界很保守：实际上 w = 9 已经够用，因为我们只要求噪点很少，不要求一个都没有。

4　论文发现的伪影，以及他们怎么修

上面的结果有一个漏洞，论文自己指出来了：分档本身会制造复杂度。设想粗粒化后是一条从 0 平滑过渡到 1 的渐变，总有一行正好落在两档的分界线上，一点点噪声就会让这一行的格子在两档之间来回跳，画出一条锯齿边（论文图 9）。这些锯齿会被 gzip 当成结构计入[1, §6.1]。

他们的修正有两步：一是把三档改成七档；二是允许每个格子上下调一档，选让文件最小的调法。精确求解要搜索 2^(n²) 种调法，所以实际用的是近似算法：一个格子如果和所在行的多数值只差一档，就把它改成多数值[1, §6.1]。

修正后的结果很能说明问题[1, §6.2]：

  • 交互模型：曲线更嘈杂，但先升后降的形状还在。
  • 非交互模型：复杂度曲线被压平到很低的水平。附录证明了原因：粒子各自独立随机游走，每一行的期望浓度可以直接算出来，块的实际浓度又以高概率贴近期望，所以粗粒化图像总能用「n 和 t」这么少的信息描述，复杂度永远不会变大。

所以论文的结论比 notebook 谨慎得多：原始方法下非交互模型的「先升后降」是分档伪影；交互模型可能真的有高复杂度的中间态。他们还强调，压缩长度只能给出 K 的上界。要证明系统真的变复杂了，需要的是下界，这还是一个开放问题[1, §7]。

5　回到 notebook 的连续扩散

notebook 的「咖啡」不是粒子，而是第 6 课讲的连续扩散：50×50 网格，中间 10×10 的方块浓度为 1，conv2d 加拉普拉斯核，r = 0.2，replicate 边界，每一步结束时 clamp(0, 1)。我用纯 Python 按同样设置跑到 2000 步，同时记下三个量：notebook 的 20 区间 histc 熵、把浓度量化成 256 级后的压缩长度（细粒度「熵」），以及三档量化后的压缩长度（「复杂度」）。

有三点值得注意：

  1. 奶油总量守恒，clamp 从来没起作用。2000 步里总量一直是 100.0000，没有一个值越过 [0, 1]。原因是新值 (1 − 4r)·v + r·(四个邻居之和) 在 r ≤ 1/4 时是五个旧值的凸组合，不可能超出旧值的范围。replicate 边界相当于墙，没有流量流出去。终态是均匀的 100/2500 = 0.04。
  2. notebook 只跑到 t = 50，所以只看到熵在升。继续跑，histc 熵在 t = 100 时是 1.31，之后开始下降，t = 1000 时降到 0：所有值都低于 0.05，全落进第一个区间。
  3. 连细粒度的压缩长度也先升后降。这不违反第二定律，而是说明这个系统里根本没有「熵」可增。演化是确定性的，第 t 步的状态可以用「初态 + t + 规则」完整描述，所以 K(xₜ) ≤ K(x₀) + K(t) + O(1)，整条轨迹都很简单。gzip 显示的上升，只说明 gzip 不会「把方块扩散 t 步」这个程序。这正是第 5 课讲的资源限制：一个算力有限的观察者看到的复杂度，可以和 K 差得很远。

所以想在模拟里看到「熵单调增、复杂度先升后降」，需要两样东西：微观上有随机性，让细粒度熵真的能增长；再加上一个够粗的粗粒化，把这些随机性抹掉。论文的粒子模型两样都有，notebook 的连续扩散一样都没有。

6　回想测验

凭记忆作答，先别往上翻。

1. 论文里的「熵」是怎么估计的？

  1. 20 区间直方图的 Shannon 熵
  2. 粗粒化分档后数组的 gzip 大小
  3. 细粒度数组的 gzip 大小
  4. 相邻格子的转换次数

细粒度数组的压缩长度估计 K(x)，也就是熵；粗粒化分档后的压缩长度估计 K(S)，是表观复杂度。

2. 完全混合后，用 9×9 窗口粗粒化，一个格子落到中间档以外的概率大约是？

  1. 32%
  2. 10%
  3. 0.3%
  4. 恰好 0

σ = 1/(2w) = 1/18，离开中间档要偏离 w/3 = 3 个标准差，2Φ(−3) ≈ 0.27%。

3. 换成调整后的粗粒化（七档 + 按行多数调整）以后，非交互模型的复杂度曲线怎样？

  1. 仍然先升后降，峰值更高
  2. 被压平到很低，附录证明它不会变复杂
  3. 单调上升，和熵一样
  4. 变成负数

粒子独立游走，每一行的浓度可以从 n 和 t 算出来，所以粗粒化图像总是简单的。原方法里的先升后降是分档伪影。

4. notebook 的连续扩散跑到 t = 2000，细粒度（256 级）压缩长度怎样？

  1. 一直上升，接近随机数组
  2. 上升后停在最高点不动
  3. 一开始就是最大值
  4. 先升到 500 多字节，再降回 26 字节

确定性演化的终态是均匀的 0.04，非常简单。K(xₜ) ≤ K(x₀) + K(t) + O(1)，gzip 的上升只是它不会运行扩散方程。

5. 为什么 r = 0.2 时 notebook 的 clamp(0, 1) 从来不起作用？

  1. 1 − 4r ≥ 0，新值是旧值的凸组合，不会超出 [0, 1]
  2. replicate 边界会自动截断
  3. conv2d 的输出总在 [0, 1] 里
  4. float32 存不下大于 1 的数

新值 = (1 − 4r)v + r·Σ邻居，五个系数都非负且和为 1。r > 1/4 时中心系数变负，才可能越界，也才会出现数值不稳定。

7　编程练习

练习 C：用 torch 复现先升后降

模拟部分用纯 Python 列表最快（逐格交换用张量反而慢），这段直接拿去用：

import random, zlib
import torch
import torch.nn.functional as F

def init(n):
    return [[1 if y < n // 2 else 0 for x in range(n)] for y in range(n)]

def run(g, n, steps, rng):
    for _ in range(steps):
        y, x = rng.randrange(n), rng.randrange(n)
        dy, dx = [(-1, 0), (1, 0), (0, -1), (0, 1)][rng.randrange(4)]
        y2, x2 = y + dy, x + dx
        if 0 <= y2 < n and 0 <= x2 < n and g[y][x] != g[y2][x2]:
            g[y][x], g[y2][x2] = g[y2][x2], g[y][x]

你要写三个函数：

  • coarse_grain(x, w)：输入 (n, n) 的 0/1 张量，返回同形状的窗口平均。用 F.avg_pool2d，它要求输入形状是 (N, C, H, W)；想想 stride、padding、count_include_pad 各该取什么[3]。
  • quantize(cg, k=3)：把 [0, 1] 的平均值分成 k 档，返回整数张量。
  • clen(x)：把整数张量转成字节串，返回 zlib.compress(..., 9) 的长度[4]。

验收：

做完以后，再试一个单变量实验：把窗口换成 3，或者把三档换成七档，只改这一处，看曲线怎么变。用第 3 节的推导解释你看到的结果。

参考解答（写完再看） 
def coarse_grain(x: torch.Tensor, w: int) -> torch.Tensor:
    x4 = x[None, None].float()                       # (n, n) → (1, 1, n, n)
    cg = F.avg_pool2d(x4, kernel_size=w, stride=1, padding=w // 2,
                      count_include_pad=False)       # 伸出边界的部分不计入平均
    return cg[0, 0]                                  # 再去掉两个长度为 1 的维度

def quantize(cg: torch.Tensor, k: int = 3) -> torch.Tensor:
    return (cg * k).long().clamp(max=k - 1)          # 1.0 本该是第 k 档，压回 k−1

def clen(x: torch.Tensor) -> int:
    return len(zlib.compress(x.to(torch.uint8).numpy().tobytes(), 9))

stride=1 让窗口每次只挪一格，输出和输入一样大；padding=w // 2 让窗口以每个格子为中心；count_include_pad=False 就是练习 A 第二问的规则，默认值 True 会把边上的格子拉向 0。x[None, None] 等价于连续两次 unsqueeze(0)，notebook 的 diffusion_2d 里写的就是后者。

我用纯 Python 实现了同样的逻辑，跑出来的数字是第 2 节表里那些。torch 用 float32，档位边界上的取整可能有个别格子不同，所以压缩长度和表里会差几个字节，但不影响三条 assert。

进阶：把 notebook 的 diffusion_2d 跑到 2000 步，用 (x * 256).long().clamp(max=255) 做细粒度量化，复现第 5 节那张表里「熵」的先升后降。环境提示：先按仓库 README 建好 .venv。

主读：Aaronson, Carroll, Ouellette，"Quantifying the Rise and Fall of Complexity in Closed Systems: The Coffee Automaton"（2014）。读第 3、5、6 节和附录，正好对应本课第 1 到 4 节。第 2 节把四种复杂度定义（表观复杂度、sophistication、logical depth、light-cone complexity）放在一起比较，可以当第 4、5 课的复习。
